# Security policy
This development release has not undergone a security audit. Do not use it for high-risk communications. Never post keys, tokens, plaintext private messages, or exploitable vulnerability details in public issues.

When a repository is published, enable GitHub private vulnerability reporting and use Security → Report a vulnerability. Until that channel exists, contact the owner privately through a verified private contact channel; do not assume an invented security address is monitored. Include affected version, reproduction steps using disposable identities, and impact. Maintainers should acknowledge privately and coordinate a fix and disclosure timeline. No response-time SLA is presently staffed. Only the latest development release receives fixes.
